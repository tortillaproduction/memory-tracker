# ゲート（Androidアプリ）実機での動作確認

ゲートを実機で確かめるための手順書です。確かめる項目は、通常の流れ、ゲートを出さずに通すケース、防御策2〜6、OSの設定からの停止です。
使う人向けのセットアップ手順は[gate-setup.md](gate-setup.md)を参照してください。

対象機種はOPPOとMotorolaです。各項目は両方の機種で確認してください。

## 0. 準備

### APKのビルド

ホストにJDKやAndroid SDKは不要です（Dockerでビルドします）。

```bash
cd android
./build.sh            # APKのビルド + 単体テスト
```

- 出力は `android/app/build/outputs/apk/debug/app-debug.apk` です。
- デバッグ用の署名鍵は、Dockerボリューム `gate-gradle-cache` に保存されます。このボリュームを消すと署名鍵が変わり、端末で上書きインストールできなくなります（その場合はアンインストールしてから入れ直します）。

### 端末へのインストール

- USBで接続する場合: `adb install -r android/app/build/outputs/apk/debug/app-debug.apk`
- 接続しない場合: APKファイルを端末に送り、ファイルを開いてインストールします（提供元不明のアプリを許可します）。

### 開発用バックエンドに接続する場合

端末からPCのバックエンドに届くよう、QRコードに埋め込むURLをLAN内のアドレスにします。

```bash
# .env
GATE_API_BASE_URL=http://192.168.0.10:8080   # PCのLAN内アドレス
```

- デバッグビルドのAPKは、平文HTTPでの接続を許可しています（リリースビルドはHTTPSのみ）。
- 本番（Vercel/Render）で確かめる場合は設定不要です（`FRONTEND_URL`が使われます）。

### 期限切れのサイトを用意する

ゲートは期限切れのサイトがあるときだけ出ます。開発環境では、シードで期限切れのサイトを作れます。

```bash
docker compose exec -T db psql -U postgres memorytracker -v email=you@example.com \
  < backend/scripts/dev_seed_overdue.sql
```

### 「今日済み」を解除して再確認する（開発環境のみ）

サイトを開くか脱出口で解除すると、その日はゲートが出なくなります。同じ日に確かめ直すには、サーバーと端末の両方の記録を消します。

```sql
-- サーバー: 今日(日本時間)のチェックインと解除の記録を消す(ストリークにも影響するので開発環境のみ)
WITH u AS (SELECT id FROM users WHERE email = 'you@example.com'),
     today AS (SELECT (now() AT TIME ZONE 'Asia/Tokyo')::date AS d)
DELETE FROM check_ins
WHERE user_id = (SELECT id FROM u) AND is_initial = false
  AND checked_at >= ((SELECT d FROM today)::timestamp AT TIME ZONE 'Asia/Tokyo');

DELETE FROM gate_dismissals
WHERE user_id = (SELECT id FROM users WHERE email = 'you@example.com')
  AND dismissed_on = (now() AT TIME ZONE 'Asia/Tokyo')::date;
```

端末の記録（今日済み、発動制限）は、デバッグビルドなら次のコマンドで消せます。消したあとは、アクセシビリティのサービスがオフになっていないかを確認し、オフならオンに戻してください。

```bash
adb shell am force-stop com.tortillaproduction.memorytracker.gate
adb shell run-as com.tortillaproduction.memorytracker.gate rm shared_prefs/gate_guard.xml
```

アプリの設定画面の **Try the gate now** は、端末側の制限（今日済み・発動制限）を無視して、サーバーの候補でゲートを出します。画面の見た目だけを確かめたいときに使います。

## 1. セットアップ

| # | 確認項目 | 期待する結果 |
|---|---|---|
| 1-1 | WebでNotificationsを **Gate** にする | Gate setup画面が開き、**Show QR code** でQRコードが出る |
| 1-2 | アプリのステップ1で **Scan QR code** → QRを読み取る | 「Connected.」と表示され、✓が付く |
| 1-3 | Webで **New QR code** を押して再発行し、古いQRを読み取る | 「This code is no longer valid...」と表示され、保存されない |
| 1-4 | ステップ2で **Open accessibility settings** → オンにして戻る | 自動で✓が付く。スイッチがグレーのときは「制限付き設定を許可」の手順で解除できる |
| 1-5 | ステップ3で **Allow** → 許可して戻る | 自動で✓が付く。機種に応じた案内（OPPO / Motorola）が表示される |
| 1-6 | ステップ4の一覧 | SNS・動画・ゲーム系だけが並び、最初はすべてオン。LINE・地図・決済・電話は出ない |
| 1-7 | ステップ5を開く | 上部に「N overdue site(s). The gate will show.」などの状況が出る |
| 1-8 | ステップ5のボタンで対象アプリを開く | ゲートが出る。アプリに戻ると「✓ The gate appeared.」になる |
| 1-9 | **Finish** | 設定画面に切り替わり、Service: On、Last gate に日時が出る |

端末の再起動は不要です。ゲートが出ない場合は再起動してから1-8をやり直し、結果を機種ごとに記録してください。

## 2. 通常の流れ

| # | 操作 | 期待する結果 |
|---|---|---|
| 2-1 | 対象アプリを開く | 期限切れのサイトが超過時間の長い順に最大3件、カードで出る（サイト名と「Nh / Nd overdue」） |
| 2-2 | カードの **Open** を押す | ブラウザでサイトが開く。Webのダッシュボードでチェックインが記録されている |
| 2-3 | 同じ日に対象アプリをもう一度開く | ゲートは出ない |
| 2-4 | 対象アプリの中で画面を移動する | ゲートは出ない（同じアプリ内の画面遷移） |
| 2-5 | Webで先にサイトを開いてから（どの経路のチェックインでもよい）対象アプリを開く | ゲートは出ない（今日済みはサーバーが判定する） |
| 2-6 | 対象にしていないアプリを開く | ゲートは出ない |
| 2-7 | 戻るボタンを押す | ゲートは閉じない |

## 3. ゲートを出さずに通すケース

どれもゲートを出さず、対象アプリがそのまま使えることを確かめます。

| # | 状況 | 作り方 |
|---|---|---|
| 3-1 | ネットワークなし | 機内モードにして対象アプリを開く |
| 3-2 | APIのタイムアウト・エラー | 開発用バックエンドを止める（`docker compose stop app`）か、到達できないアドレスにする |
| 3-3 | 候補が0件 | 期限切れのサイトがない状態にする（シードを消す: `backend/scripts/dev_seed_cleanup.sql`） |
| 3-4 | 今日すでにチェックイン済み | 2-2のあと、または Webでサイトを開いたあと |
| 3-5 | トークンが無効 | Webで **New QR code** を押して再発行する（古いトークンは使えなくなる） |

APIの応答が2秒を超えた場合は打ち切ります。そのため3-2では、対象アプリを開いてからゲートが出るかどうかが決まるまで、最大でも約2秒です。

## 4. 防御策の確認

防御策は互いに独立して働きます。1つずつ確かめてください。

### 防御策2: 無条件の脱出口

| # | 操作 | 期待する結果 |
|---|---|---|
| 4-2-1 | ゲート画面の下部を見る | 「Hold 3s to skip today」とプログレスバーが常に見えている |
| 4-2-2 | 3秒未満で指を離す | 何も起きず、プログレスバーが0に戻る |
| 4-2-3 | 3秒長押しする | ゲートが閉じ、対象アプリに戻る |
| 4-2-4 | 同じ日に対象アプリを開く | ゲートは出ない（端末の記録） |
| 4-2-5 | DBの`gate_dismissals`を見る | 今日の日付の行が1件ある（サーバーの記録） |
| 4-2-6 | 機内モードで4-2-3を行い、その日のうちに機内モードを解除して対象アプリを開く | 解除の記録が再送され、`gate_dismissals`に行ができる |

### 防御策3: 自動終了

| # | 操作 | 期待する結果 |
|---|---|---|
| 4-3-1 | ゲートを出したまま何もせず2分待つ | ゲートが自動で閉じる |
| 4-3-2 | 4-3-1のあと同じ日に対象アプリを開く | 5分経っていればゲートが再び出る（自動終了では「今日済み」にならない） |

自動終了のタイマーは、ゲート画面の外側（専用スレッド）で動いています。閉じられなかった場合は、5秒後にホーム画面へ戻す操作で強制的に外します。この経路は画面が固まったときのためのもので、通常の操作では再現できません。

### 防御策4: 発動制限

ゲートをホームボタンで閉じると（開く・解除をしないと）、「今日済み」にならずに繰り返し試せます。

| # | 操作 | 期待する結果 |
|---|---|---|
| 4-4-1 | 対象アプリAを開く → ゲートが出たらホームボタン → 5分以内にもう一度Aを開く | ゲートは出ない |
| 4-4-2 | 4-4-1から5分以上経ってからAを開く | ゲートが出る |
| 4-4-3 | 10分以内に、対象アプリを切り替えながらゲートを5回出す（例: A→B→C→5分後にA→B）。6回目に別のアプリを開く | 6回目は出ない。設定画面に「Paused until HH:MM (too many gates)」と出る |
| 4-4-4 | 4-4-3から1時間経つ | 再びゲートが出る |

発動制限の状態は端末に保存されるので、アプリのプロセスが再起動しても保たれます。

### 防御策5: システム画面の除外

対象アプリからそれぞれの画面に移り、また対象アプリに戻る、という操作を繰り返して確かめます。

| # | 画面 | 期待する結果 |
|---|---|---|
| 4-5-1 | 電話（発信・着信中の画面を含む）、連絡先 | ゲートは出ない |
| 4-5-2 | 緊急通報（ロック画面の「緊急通報」） | ゲートは出ない |
| 4-5-3 | 設定アプリ、権限のダイアログ | ゲートは出ない |
| 4-5-4 | 通知シェードを下ろして戻す | ゲートは出ない（戻っても再発動しない） |
| 4-5-5 | キーボードを出す（対象アプリの検索欄など） | ゲートは出ない |
| 4-5-6 | ホーム画面 | ゲートは出ない |
| 4-5-7 | ステップ4の一覧 | 電話・連絡先・設定・ホーム・キーボードは選択肢に出ない |

除外リストはコードに固定しています（`android/.../policy/SystemExclusions.kt`）。これに加えて、実行時に取得したホーム画面・キーボード・既定の電話アプリも除外します。どちらもユーザーの設定では外せません。

### 防御策6: OSの設定からの停止

| # | 操作 | 期待する結果 |
|---|---|---|
| 4-6-1 | 設定 → ユーザー補助 → Memory Tracker Gate → オフ | 以後、対象アプリを開いてもゲートは出ない |
| 4-6-2 | アプリの設定画面を開く | 「Service: Off」になっている |
| 4-6-3 | 設定画面の **Open accessibility settings** | このサービスの設定画面（または ユーザー補助の一覧）が開く |
| 4-6-4 | オンに戻す | 再びゲートが出る |

OSでのメニューの場所:

- **OPPO（ColorOS）**: 設定 → その他の設定 → ユーザー補助 → Memory Tracker Gate（バージョンにより「設定 → ユーザー補助と利便性」の場合もあります）
- **Motorola**: 設定 → ユーザー補助 → Memory Tracker Gate

アプリをアンインストールしても止まります。

## 5. その他の安全策

| # | 操作 | 期待する結果 |
|---|---|---|
| 5-1 | 端末を再起動し、1分以内に対象アプリを開く | ゲートは出ない。1分を過ぎてから開くと出る |
| 5-2 | `adb install -r` でAPKを更新し、1分以内に対象アプリを開く | ゲートは出ない |
| 5-3 | ゲートが出ている最中に、別の対象アプリへ切り替える | 2枚目のゲートは重ならない |

## 6. 通知バッチとの関係（Web）

| # | 状況 | 期待する結果 |
|---|---|---|
| 6-1 | 通知モードがGateで、アプリが直近3日以内にAPIを使っている | 期限切れになってもメールは届かない |
| 6-2 | 通知モードがGateで、アプリを3日以上使っていない（アンインストールなど） | メールが届く |

## 7. 結果の記録

機種ごとに、次の情報を記録してください。

- 機種・Androidのバージョン・OSのバージョン（ColorOS等）
- 1-8（初回のゲート表示）で再起動が必要だったか
- 各項目の結果（OK / NG と、NGの場合の状況）
- ステップ3の機種別の案内で、実際のメニュー名と違っていた箇所
